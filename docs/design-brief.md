# Fuel Atlas 本版设计约束

日期：2026-11-04。用户修正：保留原来的工作台结构，动效必须直接可见，并且解释加油决策。以下六项约束用于实现和验收。

## 1. 范围：在原工作台中完成一次加油决策

主任务是东亚短途宽体机既定轮转的各站加油量优化。支持 2–5 个连续航段，默认 PVG → ICN → HND → PVG。首页恢复原有油市、预测与航班计算、来源三页签，默认打开航班计算。原油市图表、来源状态、原始观测与 50 机场参考目录继续在原结构中提供；供应链情景模型另保留在 `network.html`。

本版不新增绕飞/经停优化、预测系统、账户、订单或未接通的实时报价服务。参考目录中的 50 个机场与当前轮转/报价支持的 17 个机场分别标注，不扩张可计算或报价覆盖。

## 2. 层级：保留紧凑的地图—决策—明细结构

保留原顶部品牌栏、三页签、紧凑标题与状态条。主工作区仍为左侧地图、右侧参数/成本与加油决策；轮转输入表、性能约束和逐段结果放在下方。机场报价与数据来源位于来源页签，避免将主任务排成连续宣传长页。

节省金额、比较基线、建议站点和额外耗油同时可见，不能只突出脱离条件的收益数。地图上的航段状态、燃油量与累计采购成本放在同一视区；用户不必滚动查找正在发生的变化。

## 3. 视觉：原浅色工作台与深色航空画布

页面采用原工作台的浅色背景、白色面板、细边框和蓝灰色信息层级。地图保留深海军蓝画布，地理轮廓、机场节点、弧形航路与飞机承担主体视觉，燃油和路径使用明确强调色。图表与数字稳定对齐，表单保持清晰的标签、边界和键盘焦点。

不再使用巨幅英文宣传标题改变原结构，也不照搬参考中的植物、岩石等装饰。参考中的视觉张力转译为“飞机沿路径运动、机场加油脉冲、当前航段高亮、油量与采购成本同步变化”。动画服务于解释方案，不遮挡输入、不冒充实时航迹，也不影响用户读数。

## 4. 核心交互：加载后立即看见轮转和燃油变化

有效示例方案加载后直接开始演示，无需先找到播放按钮。每一航段包括加油、飞行、到达三个可辨阶段：加油时油量与采购支出增加，飞行时油量下降，到达后衔接下一站。飞机位置、路径高亮、当前航段、油量、成本、进度和对应结果行保持联动。

提供暂停/继续、重播、进度拖动和航段选择。方案切换使用相应优化/按需结果，允许在同一位置比较两种加油策略。切换工作台页签或页面进入后台时暂停；系统减少动态效果偏好下不自动播放，静态进度仍可手动查看。

编辑轮转后立即使旧结果失效，清除旧建议并停止旧演示/导出；重新计算后更新地图、结果和演示。示例场景与用户报价明确分开，缺失/过期报价保持缺失；错误、不可行、报价待补齐与加载失败均有明确状态。CSV 导入显示逐行问题，导出带上输入、价格模式和来源。

## 5. 技术栈：静态工作台与独立的确定性动画控制器

保留现有 HTML、CSS、原生 JavaScript ES modules、SVG 和 Node/esbuild 构建测试流程。新动画控制器基于 `requestAnimationFrame`，将时间映射为航段/阶段/进度，再从当前方案计算位置、燃油与累计成本；暂停与跳转使用同一模型，不靠装饰性随机数制造动态。

报价使用原生文件读取和当前页面内存处理。轮转模型、CSV 校验、动画控制器和来源目录各为独立模块；来源卡片保留 JSON。原供应链模型继续使用已打包 LP 求解器。首页不依赖收费地图、服务器求解或前端密钥。

## 6. 验收：结构、可见动作与正确数据同时成立

- 首页保留原三页签和紧凑工作台结构；桌面地图与决策卡并列，小屏纵向排列，表格可滚动且主要操作不被裁切。
- 正常动态偏好下，首次加载有效示例后即出现飞机/加油/燃油变化；不能只有背景颜色、悬停或等待按钮后的静止画面。
- 暂停后位置和数值保持不变；继续、重播、拖动进度和选择航段均准确更新地图、阶段、燃油、成本和行高亮。
- 动画燃油与成本来自选中方案；基线和优化切换不复用旧方案或产生虚构的逐帧数值。路径明确标为方案示意。
- 离开计算页签和页面隐藏时停止后台动画；减少动态效果偏好下不自动播放且保留静态查看能力。
- 默认示例可复算；同价或价差不足时不凭空推荐提前携油；同初始、同终点库存比较，基线不可行时不显示节省比例。
- 增删或修改航段后保持连续性与 2–5 段边界；旧结果不能继续播放或导出；约束不可行时给出诊断。
- 示例价始终标为示例；用户报价须通过 CSV 口径和有效期校验，缺失值不能回退示例价。
- 来源页签保留原有数据时效、原始观测和 50 机场目录；挂牌、市场基准与到机报价不混用。
- 键盘焦点清楚，表单有标签，反馈有状态/警报语义；频繁逐帧数值不触发持续的屏幕阅读器播报。
- 模型、报价解析、动画控制器、工作台集成及原回归测试通过；桌面/手机实浏览器验证实际运动、暂停和进度，而非仅验证截图或构建。
