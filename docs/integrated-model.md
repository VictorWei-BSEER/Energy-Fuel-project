# 一个联合模型：供应商 → 运输 → 机场库存 → 飞机加油

生产实现为 [src/integrated-optimizer.js](../src/integrated-optimizer.js)，浏览器构建产物为 `dist/integrated-optimizer.js`。入口：

```js
optimizeIntegratedRotation({ ...flightInput, supplyChain })
```

`optimizeRotation` 是同一入口的别名。示例参数与用户导入的全包报价是**同一模型的两种数据输入方式**。供应链不是另算一遍机场价格后交给飞机模型：每次飞机加油量直接进入对应机场、对应事件阶段的库存平衡。供应商、运输或机场库存改变时，飞机的加油地点和携油量可以随之改变。

固定的用户航线包含 1–5 个连续航段。模型不增加经停、不改变航线或载荷、不执行采购。坐标可以来自外部目录；自动生成的经济、库存、容量、时效和性能参数仍是明确的情景假设，不因此成为真实供应商关系或实盘报价。

## 时间、单位与先后顺序

燃油和重量使用公吨，单位成本为 USD/t。每个阶段对应一次航段出发事件，阶段 `1` 是首段加油前，阶段 `n` 是末段加油前。它们不是等长小时或日历天。

每个阶段先收到到期运输，随后执行该阶段的飞机加油。运输的 `leadTimeStages` 为非负整数；阶段 `t` 出发的货物在 `t + leadTimeStages` 到达。没有初始在途货物，也不允许生成到达时点超过轮转阶段数的运输。没有在最后一个出发事件之后额外添加“免费补库阶段”。

同一机场即使在航线中出现多次，也只有一组持续演进的地面库存。供应商每阶段上限和整个轮转的总上限由其所有运输路径共同使用，不为每个机场复制一份。

## 联合变量与约束

主要决策量为每段飞机额外携油 `E_i`、本站加油 `U_i`、供应商至机场的运输量 `X_r,t`，以及机场阶段末库存 `G_a,t`。采购量是供应商当阶段所有运输发出的合计；不另设可以重复收费的“飞机购油量”。

飞机方程直接共用 [flight-optimizer.js](../dist/flight-optimizer.js) 的校验及物理计算函数，不另写一套性能定义。设滑行耗油 `T_i`、基础空中耗油 `B_i`、到达保留油 `R_i`、本航段携油损耗比例 `k_i`：

```text
滑行前油量 = T_i + B_i + R_i + E_i
起飞油量   = B_i + R_i + E_i
落地油量   = R_i + (1-k_i) E_i
U_i        = 滑行前油量 - 上一段落地油量
首段 U_1   = T_1 + B_1 + R_1 + E_1 - 初始机上油量
额外耗油   = k_i E_i
```

要求 `E_i ≥ 0`、`U_i ≥ 0`，并保持原有滑行前油箱、最大起飞重量、最大落地重量、每次到访加油上限和保留油约束。模型不通过卸油修复初始库存过多，也不使用“未满足需求”松弛变量凭空满足航班耗油；整个轮转必须可执行才返回可行。

机场库存约束为：

```text
G_a,t = G_a,t-1 + 到达机场 a 的运输量 - 此阶段在 a 的飞机加油量
开场库存 + 本阶段收货量 ≤ 机场储存容量
阶段末库存 ≥ 机场地面保留库存
末阶段库存 = 明确的机场终点库存目标
```

此外，所有运输满足各路径阶段上限、可选路径全轮转上限、供应商阶段共享上限与供应商全轮转共享上限。提前收货必须占用机场储存容量并承担设定的持有成本。

## 同一成本目标，不重复收费

`mode: "modeled"` 按实际决策量分别计入：

| 成本字段 | 计费对象 |
| --- | --- |
| `procurementUsd` | 运输发出量 × 该供应商、该阶段的产品价格 |
| `freightUsd` | 运输量 × 路径运费 |
| `handlingUsd` | 运输量 × 路径装卸费 |
| `basisAdjustmentUsd` | 运输量 × 显式机场/合同差价调整，可正可负 |
| `holdingUsd` | 每阶段末地面库存 × 每吨每阶段持有费 |
| `intoPlaneUsd` | 飞机加油量 × 机场加注服务费 |
| `taxAdjustmentUsd` | 飞机加油量 × 显式税费调整，可正可负 |

产品、运费、装卸和差价合计的**加注前获取成本不得为负**；其与加注服务和税费的总和也不得为负。正的全包价不能掩盖负的产品获取成本，从而通过囤积未使用终点库存取得虚假补贴。若手工全包价低于所设服务费，需修正分项或使用直接报价模式，不能把矛盾埋入负采购价。

机场表中原有 `legs[].priceUsdPerT` 是输入价格参照和性能输入结构的一部分，**不会再额外乘以飞机加油量加入联合目标**。初始飞机与机场燃油视为已持有，不重新购买；地面初始库存仍会按实际剩余量产生设定的持有费。

`mode: "delivered"` 采用直接全包报价交付弧，成本仅进入 `deliveredQuoteUsd`。供应商和上游运输集合必须为空，机场的模型加注、税费和持有收费必须为零，避免在导入的全包价格之上再叠一套假设费用。报价仍受其事件阶段可用量、全轮转总量、机场库存及飞机约束限制；未来事件才可用的报价不能提前使用。报价弧是直接交付采购选项，并不声称观测到了背后的炼厂、运输路径或库存。若合同不允许预置库存，用户应相应限制报价可用阶段与地面库存条件。

## 公平基线

基线先由共用飞机物理核心确定逐站最低加油的机上携油量，再将这些飞机决策固定，**求解同一供应链 LP**。优化方案允许改变携油与加油量，其他产品、费用、上限、库存和时效条件保持相同。

两方案使用相同的初始飞机燃油，末段落地燃油都等于逐站最低加油参考的末段落地燃油。每个机场也使用相同初始库存和**完全相等**的终点库存目标；`terminalInventoryT` 未给出时默认等于该机场初始库存。可配置不同于初始值的终点目标，但它必须在两方案中相同。

因此，节省不能来自一边把机上或地面库存耗尽、另一边补齐库存。基线本身已经选择其固定加油需求下最低成本的上游采购路径，单航段不会把“基线没优化采购”产生的差额伪称为携油节省。

若逐站最低加油不能在同一上游网络中获得供应，但提前携油可以完成轮转，仍返回可行联合方案；`savingsUsd`、`savingsPercent`、`extraBurnVsBaselineT` 为 `null`，不和不可行参考报告节省。无法数值验证的参考也不会产生节省宣称。

## 输入结构

原有 `initialFuelT`、`aircraft`、`legs` 字段见 [飞机物理核心](flight-model.md)。新增：

```js
supplyChain: {
  mode: "modeled", // 或 "delivered"
  suppliers: [{
    id: "shared-pool",
    priceUsdPerT: 800,       // 标量或长度 n 的阶段数组
    capacityT: 100,          // 标量或长度 n 的阶段数组
    totalCapacityT: 200      // 强制有限的全轮转共享上限
  }],
  routes: [{
    id: "lane-1", supplierId: "shared-pool", airport: "PVG",
    capacityT: 60, totalCapacityT: 100,
    leadTimeStages: 0, freightUsdPerT: 20,
    handlingUsdPerT: 0, basisAdjustmentUsdPerT: 0
  }],
  airports: [{
    code: "PVG", initialInventoryT: 0, terminalInventoryT: 0,
    storageCapacityT: 60, reserveT: 0,
    intoPlaneUsdPerT: 30, taxAdjustmentUsdPerT: 0,
    holdingUsdPerTPerStage: 0.5
  }],
  deliveredOffers: []
}
```

报价模式将 `suppliers`、`routes` 置空，并使用：

```js
deliveredOffers: [{
  id: "airport-offer", airport: "PVG",
  priceUsdPerT: [920, 0], capacityT: [60, 0], totalCapacityT: 60
}]
```

标量容量/价格广播至所有事件阶段，数组必须精确覆盖阶段数。报价不可用的阶段应将容量置零。路径和报价的全轮转上限可省略，此时采用其阶段容量总和；供应商的全轮转共享上限必须显式给出。地面机场集合必须恰好覆盖所有出发站，重复访问仅建一条机场记录。

## 输出与显示归因

保留原 `optimizeRotation` 的 `feasible`、`legs`、`totalCostUsd`、燃油合计、`baseline`、节省等字段；额外提供 `optimized` 方案对象。每个有效方案的 `supplyChain` 包含：

- `suppliers`：各共享池总采购及上限。
- `shipments`：来源、机场、出发/到达事件阶段、数量和分项成本；输出阶段从 1 开始。
- `airportInventory`：每个机场每阶段的开场、收货、加油、末库存、保留量和容量。
- `terminalTargets`：相同的初始、目标及实际末库存。
- `costBreakdown`：上述成本分项及 `totalUsd`。
- `airportCosts`：按机场汇总的完整供应成本。

每段 `legs[].costUsd` 是**归属机场全轮转成本按该站各次加油量比例分摊**的展示值，不是该次加油的边际报价。若某站没有加油但仍有持有费，费用归属该站首次访问。`costAllocation` 明示这一规则，全部航段归属成本之和等于联合总成本；分析现金流和运输时点时应读取分项运输与库存表。

稳定错误类别在 `errorDetails` / `diagnosticDetails` 中：`INVALID_FLIGHT_INPUT`、`INVALID_SUPPLY_CHAIN`、`NEGATIVE_ACQUISITION_COST`、`JOINT_NETWORK_INFEASIBLE`、`BASELINE_NETWORK_INFEASIBLE`、`NUMERICAL_VALIDATION_FAILED`。保留原字符串错误列表供现有界面使用。数值核验不通过不会被称为物理不可行或全局最优。

## 求解、核验与范围

使用 `javascript-lp-solver` 的连续 LP；为避免其可选预处理器的冗余约束问题，关闭预处理。先无量纲化燃油和价格后求解，防止微小但高价值的采购量被固定吨数容差抹去。无量纲求解精度为 `1e-14`；机上状态仍由原飞机核心重新核验，地面质量平衡、共享上限与终点库存另行按质量尺度核验，不采用固定的绝对吨数容差下限。

成本相同至数值精度时，可用第二次 LP 减少不必要的额外携油；若可选的第二次求解无法验证，则保留已经验证的原始成本最优结果。若所谓最优成本明显高于可行基线，返回数值错误，不能仅改用基线后继续声称已经证明最优。

测试覆盖上游中断改变加油地点、共享阶段/全轮转容量、重复机场持续库存、延迟交付、相同终点库存、全包报价只收费一次、单段零携油节省，以及质量和单价反向缩放后的成本不变性。独立 SciPy/HiGHS 核验采用落地油量变量，与生产模型的额外携油变量不同，脚本为 `scripts/audit-integrated-model.py`。

这仍是固定航线、单架飞机、单种可分割燃料的线性情景模型。尚未纳入船舶/车辆整数批次、运输实际小时与排班、多架飞机竞争需求、质量混配、合同最低提货、真实罐区拓扑、金融对冲与税务适用性；飞机性能也仍取决于用户或生成情景的输入。页面组织上的合并代表决策约束的真实耦合，不代表这些缺失的商业或运行细节已经被观测和实现。
